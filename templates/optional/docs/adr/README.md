# 架构决策记录（ADR）

只有重要选择的理由、备选方案和后果值得长期保留时，才创建 ADR。普通任务拆解放 PLAN，术语放 GLOSSARY；docs 还可以承载其他独立文档，不限于本目录。

## 如何取用

1. 在目标项目需要记录首个决策时创建 docs/adr/，将本说明和 [TEMPLATE.md](TEMPLATE.md) 一起取用。
2. 复制 TEMPLATE.md 为 0001-简短标题.md，后续按序编号；模板本身不占决策编号。
3. 写清实际取舍，由用户确认决策内容，再在项目的 README 或 AGENTS 补上入口。

## 如何维护

草稿在确认前可以修改。决策采纳后保留当时的理由；改变实质选择时新增一篇并引用旧编号，说明替代关系，不覆盖原决策历史。

只有真实发生的取舍才写成已采纳决策。尚未决定时保留草稿状态，不把候选方案写成既定事实。
